Коротко: система не вгадує, а звіряє ваші відповіді з набором правил і щоразу питає те, чого бракує найближчому до виконання правилу.

## Складові експертної системи

| Складова | Де в проєкті |
|---|---|
| База знань (факти й правила) | колекції `symptoms` і `rules` у MongoDB |
| Блок логічного виводу | `DiagnosisService` на сервері |
| Керування діалогом | `ConsultationService` на сервері |
| Інтерфейс користувача | екран діагностики в застосунку |
| Редактор знань | вкладка «Редактор» |
| Пояснення | рядок «Чому: …» та блок гіпотез |

Усю логіку обчислень виконує **сервер**, а застосунок лише показує результат. Тому правила можна змінити в одному місці, і це відразу діє для всіх.

## База знань

**Факт** (ознака) — те, про що питають:

```json
{ "code": "s_overheat", "label": "Перегрів двигуна", "group": "Робота двигуна" }
```

**Правило** — зв'язок «умови → висновок»:

```json
{
  "ruleCode": "R2",
  "conditions": ["s_starter_yes", "s_spark_no"],
  "conclusionCode": "c2",
  "conclusionText": "Несправна система запалювання..."
}
```

Усю базу знань показано на схемі: ліворуч ознаки, посередині правила, праворуч висновки. Кружечок «І» означає, що потрібні всі умови одразу.

## Логічний вивід (прямий ланцюг)

1. Відмічені «Так» ознаки потрапляють у робочу пам'ять.
2. Сервер перебирає правила. Якщо **всі** умови правила є в пам'яті, воно спрацьовує, а його висновок додається в пам'ять.
3. Крок 2 повторюється, поки з'являються нові висновки. Завдяки цьому один висновок може стати умовою іншого правила.

## Як вибирається наступне питання

Сервер не зберігає стан діалогу: застосунок щоразу надсилає **всі відповіді**, а сервер рахує все наново.

1. З відповідей складається список відомого. Додаються очевидні наслідки: «іскра є» означає, що «немає іскри» неправда.
2. Правила, яким відповіді суперечать (або умову яких пропущено через «Не знаю»), відкидаються.
3. Для кожної невідомої умови живих правил нараховується бал `1 / (скільки умов у цьому правилі ще невідомі)`. Правило, якому лишилась одна умова, дає найбільше.
4. Питання з найбільшою сумою балів ставиться наступним.
5. Діалог завершується, коли питати нічого або вже дано 8 відповідей.

Так, наприклад, після відповіді «Стартер крутить: Так» система питає про іскру: це одна з двох умов правила R2, тож питання найшвидше наближає до висновку.

## Обмеження

- Усі правила рівноцінні: система не знає, яка поломка трапляється частіше.
- Немає ймовірностей чи коефіцієнтів упевненості: правило або спрацювало, або ні.
- Умови поєднуються лише через «І».
- Відповідь «Не знаю» повністю виключає правила, яким потрібна ця ознака.
